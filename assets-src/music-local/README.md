# Локальные треки для тестов

Папка для **своих** аудиофайлов, на которых хочется проверить игру (в том числе коммерческих). Всё,
что здесь лежит, и всё, что из этого генерируется, остаётся на этом компьютере: в git не попадает
(`.gitignore`), в production-сборку и на Vercel — тоже (`scripts/vite-local-tracks.ts` удаляет
`dist/local` после сборки, `.vercelignore` не даёт загрузить исходники).

## Как пользоваться

1. Положить сюда файлы `mp3 / ogg / wav / m4a / flac` (также `aac / opus / wma / webm`).
   Имя вида `Исполнитель - Название.mp3` разбирается на исполнителя и название (разделитель —
   дефис или тире с пробелами; ведущий номер трека `03 - ` отбрасывается). Любое другое имя целиком
   становится названием.
2. `npm run assets:local` — для каждого файла:
   - id = slug имени файла, кириллица транслитерируется: `Noize MC - Лебединое озеро.mp3` →
     `noize-mc-lebedinoe-ozero`;
   - ffmpeg с теми же настройками, что у встроенных треков (обрезка до 150 с, нормализация
     громкости, затухание, 128 kbps) → `public/local/music/<id>.mp3`;
   - тот же анализ, что для встроенных карт и «Своей музыки» → `public/local/charts/<id>.json`;
   - `public/local/catalog.json` — список для меню.
   Уже сконвертированный mp3 не пересчитывается, пока исходник не изменился;
   `npm run assets:local -- --force` перекодирует всё.
3. `npm run dev` (или `npm run build && npx vite preview`) — в списке треков появляется секция
   **«Локальные треки»**, каждая карточка с бейджем **ЛОКАЛЬНО**.

## Что отличается от встроенных треков

- всегда открыты, не бывают треком дня, не отправляются в онлайн-таблицу;
- рекорд и история попыток сохраняются как у встроенных (`trackId = id`);
- в сумму звёзд встроенного каталога и в цели не входят;
- жанр `local`: обложка и тема — по умолчанию (по хэшу id).

Удалил файл отсюда — при следующем `assets:local` он исчезнет из каталога, но его mp3/json в
`public/local/` скрипт не трогает (напишет, какие остались) — удалять руками.
