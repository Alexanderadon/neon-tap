## 0. Музыка: почему в игре нет чужих хитов

Нарушение авторского права возникает в момент **воспроизведения и распространения**, а не получения прибыли. Некоммерческое использование влияет на размер компенсации, а не на законность. Практические последствия для хостинга:

| Где хостится | Что произойдёт с лицензионными треками |
|---|---|
| GitHub Pages / Vercel | DMCA takedown → проект отключают, аккаунт получает страйк |
| Резюме | **мёртвая ссылка** — худший исход для портфолио |

Piano Tiles-клоны с лицензионными треками снимают регулярно; osu! держит отдельный DMCA-процесс; Beat Saber и Guitar Hero покупали лицензии. Тимлид, глядящий портфолио, знает про DMCA — игра с ворованными треками читается как минус.

### Двухслойная модель контента

1. **Встроенный саундтрек** — 16 треков под **CC0** (public domain) с OpenGameArt: synthwave, EDM, drum&bass, hardstyle, techno. Реестр: `assets-src/tracks.json`, отчёт по лицензиям: `public/music/LICENSES.md`.
2. **«Своя музыка»** — игрок кидает MP3/OGG/WAV, движок сам генерирует карту через onset-detection в Web Audio API. Файл не покидает браузер, ничего не распространяется → нарушения нет.

Второй пункт важнее первого: автогенерация карт из произвольного аудио — единственная фича, которую нельзя списать с туториала. Именно она в первом абзаце README.

### Почему OpenGameArt, а не Pixabay

Pixabay требует логин для скачивания и не отдаёт музыку через API — пайплайн нельзя воспроизвести скриптом. OpenGameArt даёт прямые ссылки и CC0-фильтр; каждый файл в репозитории восстанавливается командой `npm run assets:music` из реестра.

| **Комбо и страх его потерять** (loss aversion) | Комбо крупно, шрифт `32 + min(combo, 500)·0.06`; цвета на порогах 50 → cyan, 100 → фиолетовый, 250 → золото, 500 → белый с пульсацией. | **Незакрытый прогресс** (Зейгарник) | Счётчик «★ N / 63» над списком и ранг на каждой карточке — что не закрыто, видно сразу. | `widgets/track-list` |
| **Juice** | Вспышка полосы 80 мс, пул 300 частиц без аллокаций, shake ≤ 4 px только на промахах и порогах комбо, пульсация фона в такт, предрендеренное свечение (не `shadowBlur` в кадре). | `shared/lib/render/*` |

## 3. Концепт

**Название:** NEON TAP
**Жанр:** ритм-игра на 3–5 полос, браузер, desktop + mobile
**Сессия:** 90–150 секунд на трек
**Управление:** `D F J K` при 4 полосах; 3 → `D F J`, 5 → `D F G/H J K`; круги — тап по кругу на экране или `Space`; на мобиле — тач-зоны по числу полос в нижней половине экрана, слайд — ведёшь палец в соседнюю зону
**Стиль:** тёмный фон, неоновые полосы (cyan / magenta / lime / orange / violet), виньетка, полосы физически разъезжаются и сливаются при смене их числа

### Прогрессия

**v1.3:** миров нет. Один плоский список из 31 трека, отсортированный по звёздам песни (★4–7 во встроенном контенте), на каждой карточке — процедурная обложка (SVG из хэша id и жанра: `entities/track/ui/TrackCover`), жанр и темп, теги механик (смена полос / круги / дроби / слайды / холды) и лучший ранг. Жанр (`genre`) задаётся в `assets-src/tracks.json` и попадает в `ChartFile` и `TrackMeta`. Всё открыто сразу (флаг `UNLOCK_ALL` в `shared/config/constants.ts` зарезервирован под будущую прогрессию). Одна карта на песню: сложность — свойство самой песни, а не выбор в меню.

Звёзды: 1 за прохождение (ранг ≥ C), +1 за ранг A, +1 за ранг S. 31 трек → максимум 93 ★. Сохранение — `entities/progress` (v2: `tracks[id] = лучший результат`; старые сохранения с тремя сложностями мигрируют, беря лучший).

### Русская озвучка

16 фраз: «Отлично!», «Молодец!», «Так держать!», «Идеально!», «Не сдавайся!», «Огонь!», «Комбо пятьдесят / сто / двести пятьдесят / пятьсот!», «Полное комбо!», «Поехали!», «Новый рекорд!», «Ранг эс!», «Мимо!», «Ещё разок?».

Реализация: MP3, нейросетевые голоса ru-RU-DmitryNeural и ru-RU-SvetlanaNeural (`scripts/generate-voice.ts`, клиент `msedge-tts`), игрок выбирает голос или выключает диктора в настройках. Фолбэк — Web Speech API `ru-RU`. Отдельный слой громкости. Рейт-лимит 2.5 с, приоритетные фразы (пороги комбо, результат) его обходят.

### Звуковые эффекты

CC0-сэмплы из паков Kenney (реестр `assets-src/sfx.json`, выбраны по объективным метрикам `scripts/analyze-samples.ts`: длительность, атака, спад, спектральный центроид):

| Событие | Сэмпл | Почему |
|---|---|---|
| Попадание | `impactGeneric_light` ×5 round-robin | мягкий удар 70–140 мс, центроид ~1 кГц — не режет при 8 нотах/с; Great/Good тише и ниже по питчу |
| Промах | `impactSoft_heavy` ×3 | глухой низкий «бум» ~100 Гц + lowpass-провал на мастере |
| Потеря комбо ≥ 10 | `impactGlass_medium` ×2 | «комбо разбивается как стекло» |
| Порог комбо | `confirmation_002` | двухтоновый восходящий чайм |
| Метроном | `click_001` / `drop_001` | короткий крисп 15 мс, чётко слышимая атака для калибровки |
| UI | `click2` | нейтральный клик |

Если сэмпл не загрузился, играет минимальный синтезированный заменитель — игра не должна замолкать из-за 404.

## 4. Технический стек

```
UI         React 18 + TypeScript strict, Feature-Sliced Design
Рендер     Canvas 2D + offscreen-слой статики + предрендер glow-спрайтов
Аудио      Web Audio API — без библиотек
Анализ     собственный FFT → spectral flux → автокорреляция → генератор карт; Web Worker
Сборка     Vite, vitest, eslint (+ boundaries), GitHub Actions
Состояние  собственный store на useSyncExternalStore, localStorage
Хостинг    Vercel
Рантайм-зависимости: react, react-dom. Всё остальное — свой код.
```

**Почему React, если «ноль зависимостей»:** React отвечает только за экраны-меню. Игровой цикл, аудио, судейство, рендер нот и анализ сигнала — чистый TypeScript в `shared/lib` и `features/play-chart`, и именно они — предмет разговора на собеседовании. Открыв `package.json`, работодатель не увидит `phaser` или `tone.js`.

### Критические технические требования

**1. Единственный источник времени — `audioContext.currentTime`.**

```ts
// shared/lib/audio/Clock.ts
songTime() { return audioNow() - startTime - userOffset; }
```

`requestAnimationFrame` — только для отрисовки. Таймстампы событий ввода (`event.timeStamp`) переводятся в аудиовремя, чтобы компенсировать задержку между нажатием и обработчиком.

**2. Калибровка задержки — при первом запуске.** Метроном 120 BPM планируется look-ahead-планировщиком на аудиочасах; игрок тапает 16 раз; медиана отклонений → `settings.audioOffsetMs`. Ручной слайдер −300…+300 мс в настройках.

**3. Окна попадания.**

```ts
HIT_WINDOWS = { perfect: 0.045, great: 0.090, good: 0.135 } // с; дальше — miss
```

**4. Момент появления ноты.** `approachTime = 1.6 с / scrollSpeed` (1.0–3.0×); `spawn = hitTime − approachTime`, координата `y = hitY − (hitTime − songTime) · hitY / approachTime`.

### Формат карты

```json
{
  "id": "neon-hyperdrive", "title": "Neon Hyperdrive", "artist": "adiutorium",
  "license": "CC0 1.0", "sourceUrl": "https://opengameart.org/content/neon-hyperdrive",
  "audio": "music/neon-hyperdrive.mp3", "bpm": 139.8, "offset": 0.093, "duration": 129.6,
  "beats": [0.093, 0.522, 0.951],
  "chart": {
    "stars": 5,
    "notes": [[0.500, 0], [12.4, 1, 0.86], [14.1, 2, 0, "slow"], [20.2, 3, 1.2, "slide", 2], [31.0, 1, 0.55, "roll", 4], [48.1, 0, 0, "circle"]],
    "sections": [[0, 4], [27.4, 5], [55.1, 3]]
  }
}
```

`notes` — `[t, lane]` тап; `[t, lane, dur]` холд (голова + хвост); `[t, lane, 0, 'slow' | 'heart']` спелл; `[t, lane, dur, 'slide', endLane]` слайд в соседнюю полосу (хвост засчитан, если в момент конца зажата `endLane`); `[t, lane, dur, 'roll', taps]` дробь (`taps` нажатий за `dur`, ≥ ½ — Good, все — Perfect); `[t, lane, 0, 'circle']` круг (нумеруется внутри группы, тап по кругу на экране). `sections` — `[t, laneCount]`, 3–5 полос; без секций — 4. `beats` — доли трекера.

### Автогенератор карт (ключевая фича)

Принцип v1.3: **ноты стоят на реальных ударах музыки** (локальные пики силы удара на сетке 16-х), а не на шаблоне — играешь «по слуху», как будто сам бьёшь по барабанам; шаблоны ритма остались только как справочник для тестов.

1. `decodeAudioData` → `AudioBuffer` → моно-микс 22 050 Гц (в Node — ffmpeg → f32le).
2. STFT: окно Ханна 1024, hop 512, собственный radix-2 FFT.
3. **Spectral flux**: Σ max(0, log(1+10·|X_t|) − log(1+10·|X_{t−1}|)); отдельно по полосам 20–250 / 250–2000 / >2000 Гц; плюс энергия середины (250–2000 Гц) на кадр — для холдов.
4. Онсеты: адаптивный порог (скользящее среднее ±10 кадров × 1.5), локальные максимумы, ≥ 50 мс между ударами.
5. Темп: автокорреляция огибающей flux (60–220 BPM), бонус за кратные лаги, параболическая интерполяция, фолд в 90–180.
6. **Трекер долей** (`BeatTracker.ts`, динамическое программирование Эллиса, как в librosa): доли ставятся на сильные удары *и* держат ровный шаг; Σ score(beat) − tightness · Σ log²(Δt/период). Дрейф от неточного BPM исключён — сетка следует за реальной музыкой. Даунбит — фаза с максимумом басовой энергии.
7. **Сетка**: 16 слотов на такт между соседними долями. На каждый слот: сила удара (0..1, норма по p95), доли полос, `sustain` — сколько слотов подряд середина держит ≥ 50 % энергии.
8. **Динамика**: интенсивность такта 0/1/2 по сглаженной средней силе (квантили q35/q70 с абсолютными порогами).
9. **Ноты по слуху**: слот получает ноту, если его сила (× буст тихой фразы) — локальный максимум среди соседних 16-х (удар именно здесь), не ниже 42 % от p90 фразы и не ниже абсолютного пола 0.05 (тишина остаётся пустой). Приоритет: доли (+0.15) > восьмые (+0.05) > 16-е (−0.12); лимит нот на такт по интенсивности [2 / 4 / 6] (на 3 полосах ≤ 5), между обычными нотами ≥ восьмая, глобально ≤ 3.5 нот/с (лишние — слабейшие — выбрасываются).
10. **Дроби (roll)**: (а) сбивка — последняя доля/две такта, где звучит *каждая* 16-я и офф-16-е заметно громче, чем в остальном такте; (б) «стрим» припева — четыре слышимые восьмые второй половины такта, с шансом 0.45 и паузой 2 такта; (в) тянущийся басовый звук. Нажатий ≤ 6 в секунду: на быстрых песнях дробь укорачивается или остаётся тапами.
11. **Холды и слайды**: нота на слоте с `sustain ≥ 2` и не басовом ударе становится длинной (до 16 слотов, бюджет 3 на такт, шанс выше в тихих частях). Холд ≥ доли с шансом 0.4 становится **слайдом** в соседнюю свободную полосу; на время слайда других нот нет вообще (палец едет — тапать нечем).
12. **Два пальца**: не больше одной длинной ноты (холд / дробь / слайд) одновременно; аккорды (2 ноты) только на сильных долях, когда ничего не зажато и не внутри стрима.
13. **Круги**: первые 2 такта каждой интенсивной фразы (припев, дроп) — окно только кругов: обычные ноты убраны (и за долю до окна), 4 круга на сильнейших ударах окна, ≥ доля между ними, зигзаг по полю (лево / право / центр…). Режимы не смешиваются.
14. **Полосы**: стримы — «лесенка вверх/вниз», «зигзаг», «трель» (меняются каждый такт); редкие ноты — бас слева, верх справа; правило «≤ 2 подряд в одну полосу» (аккорды и круги считаются). **Секции**: каждая 8-тактовая фраза получает число полос по интенсивности — тихо 3, средне 4, припев 5; интро всегда 4; переход происходит, как только исчезла последняя нота старой секции (до появления новых), перед ним 2 доли тишины.
15. **Спеллы**: с 4-го такта каждые 8 тактов первый обычный тап — спелл: чередуются «замедление» и «сердце».
16. Звёзды: `avgNps·2.4 + max(0, peakNps − avgNps)·0.6 + holdShare + specialShare·3 + tempo·1.2 − 0.6`, где `tempo = clamp((bpm − 120) / 70)`, `specialShare` — доля слайдов, дробей и кругов. Скорость нот — своя у песни: 3.5 доли на подлёт (1.3–2.4 с).

Работает в Web Worker с прогрессом по стадиям (удары → доли → сетка → раскладка). Тот же модуль запускается в Node для встроенных треков — карты игрока и встроенные карты делает один и тот же код.

### Жизни, спеллы, тач-помощь

- **5 сердец**: промах −1, 25 чистых попаданий подряд +1, спелл «сердце» +1 (максимум 5). Ноль сердец — провал, результат не засчитывается, RETRY.
- **Спелл «замедление»**: неоновые песочные часы в кольце; поймал — 6 секунд песни идут в 0.72× скорости *вместе с музыкой* (playbackRate + «плёночный» lowpass, вход 0.35 с, выход 0.5 с), часы и судейство идут по тому же замедленному времени, ритм не сбивается; индикатор над полем.
- **Автоподстройка задержки**: медиана последних 40 ошибок тайминга по половине вносится в оффсет (до ±80 мс); после трека с ≥ 60 попаданиями сохраняется в настройки.
- **Тач-помощь** (по умолчанию на телефоне, выключается в настройках): нажатие до 0.4 с *раньше* ноты «заряжает» её, и она засчитывается как Great, когда доходит до линии. На ПК тайминг строгий.

### Спецэффекты

Предрендер + пулы, без аллокаций в кадре: кольцо на Perfect, шлейф за нотой, подпрыгивание рецептора на каждом нажатии, «+очки» под судейством, искры из рецептора во время холда/дроби/слайда, счётчик «2/4» над дробью, полосатое тело дроби и наклонное тело слайда с шевронами и маркером пальца, пунктирная связка между соседними кругами, ударная волна и бегущий баннер «N COMBO» на порогах комбо, дрожь и «прыжок» цифры комбо от 20, взрыв частиц и тряска при потере сердца, «удар камеры» (зум 1.2 %) и подсветка поля на басовых ударах *самого трека* (AnalyserNode, а не сетка), смена числа полос — разделители и рецепторы физически съезжаются/разъезжаются с лёгким перелётом и световыми шлейфами, большая цифра нового числа полос, вспышка всех рецепторов в момент фиксации.

## 5. Тесты

`vitest`, окружение node, без DOM — движок спроектирован так, чтобы тестироваться без браузера:

- `Clock` — дрейф, offset, пауза/резюм
- `Scoring` / `judgeDelta` — окна, точность, ранги, «до S не хватило N»
- `NoteManager` — судейство таймингов, холды, авто-мисс, курсоры
- `OnsetDetector` — синтетический сигнал: ≥ 90 % онсетов в ±30 мс без потока ложных
- `BpmEstimator` — 128 BPM ± 2
- `ChartGenerator` — квантование, кап плотности, «≤ 2 подряд», монотонные звёзды, детерминизм
- `SaveData` — миграции, звёзды, слияние результатов
- `Calibration` — медиана против выброса
- `ParticlePool` / `ScreenShake` — ёмкость, амплитуда ≤ 4 px
