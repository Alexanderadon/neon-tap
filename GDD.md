## 0. Музыка: почему в игре нет чужих хитов

Нарушение авторского права возникает в момент **воспроизведения и распространения**, а не получения прибыли. Некоммерческое использование влияет на размер компенсации, а не на законность. Практические последствия для хостинга:

| Где хостится | Что произойдёт с лицензионными треками |
|---|---|
| GitHub Pages / Vercel | DMCA takedown → проект отключают, аккаунт получает страйк |
| Резюме | **мёртвая ссылка** — худший исход для портфолио |

Piano Tiles-клоны с лицензионными треками снимают регулярно; osu! держит отдельный DMCA-процесс; Beat Saber и Guitar Hero покупали лицензии. Тимлид, глядящий портфолио, знает про DMCA — игра с ворованными треками читается как минус.

### Двухслойная модель контента

1. **Встроенный саундтрек** — 16 треков под **CC0** (public domain) с OpenGameArt: synthwave, EDM, drum&bass, hardstyle, techno. Реестр: `assets-src/tracks.json`, отчёт по лицензиям: `public/music/LICENSES.md`.
2. **«Своя музыка»** — игрок кидает MP3/OGG/WAV, движок сам генерирует карту через onset-detection в Web Audio API. Файл не покидает браузер, ничего не распространяется → нарушения нет.

Второй пункт важнее первого: автогенерация карт из произвольного аудио — единственная фича, которую нельзя списать с туториала. Именно она в первом абзаце README.

### Почему OpenGameArt, а не Pixabay

Pixabay требует логин для скачивания и не отдаёт музыку через API — пайплайн нельзя воспроизвести скриптом. OpenGameArt даёт прямые ссылки и CC0-фильтр; каждый файл в репозитории восстанавливается командой `npm run assets:music` из реестра.

## 1. Что даёт зависимость — исследование → механики

| Рычаг | Механика | Где в коде |
|---|---|---|
| **Комбо и страх его потерять** (loss aversion) | Комбо крупно, шрифт `32 + min(combo, 500)·0.06`; цвета на порогах 50 → cyan, 100 → фиолетовый, 250 → золото, 500 → белый с пульсацией. При промахе комбо разлетается частицами + звук «стекло». | `features/play-chart/lib/Renderer.ts`, `shared/lib/audio/sfx.ts` |
| **Промах ломает музыку** | Lowpass 800 Гц на мастер-канал + −40 % громкости на 250 мс. Наказание слышно, а не только видно. | `AudioEngine.missEffect()` |
| **Near-miss** | Экран результатов: разбивка Perfect/Great/Good/Miss и «до ранга S не хватило N нот». RETRY — крупнейшая кнопка, в фокусе. | `entities/score/notesToReach`, `widgets/result-breakdown` |
| **Нулевое трение рестарта** | Трек в памяти (`AudioBuffer`); рестарт = сброс индексов + `source.start()`. Хоткей `R`. Переходы ≤ 200 мс. | `GameSession.restart()` |
| **Flow** | Звёзды 1–10 на песню (плотность, пики, доля механик, темп); плоский список от лёгких к сложным, лучший ранг на карточке. | `ChartGenerator.rateStars`, `widgets/track-list` |
| **Незакрытый прогресс** (Зейгарник) | Счётчик «★ N / 63» над списком и ранг на каждой карточке — что не закрыто, видно сразу. | `widgets/track-list` |
| **Juice** | Вспышка полосы 80 мс, пул 300 частиц без аллокаций, shake ≤ 4 px только на промахах и порогах комбо, пульсация фона в такт, предрендеренное свечение (не `shadowBlur` в кадре). | `shared/lib/render/*` |

## 3. Концепт

**Название:** NEON TAP
**Жанр:** ритм-игра на 3–5 полос, браузер, desktop + mobile
**Сессия:** 90–150 секунд на трек
**Управление:** `D F J K` при 4 полосах; 3 → `D F J`, 5 → `D F G/H J K`; круги — тап по кругу на экране или `Space`; на мобиле — тач-зоны по числу полос в нижней половине экрана, слайд — ведёшь палец в соседнюю зону
**Стиль:** тёмный фон, неоновые полосы (cyan / magenta / lime / orange / violet), виньетка, полосы физически разъезжаются и сливаются при смене их числа

### Прогрессия

**v1.3:** миров нет. Один плоский список из 59 треков, отсортированный по звёздам песни (★2–9 во встроенном контенте; 6 премиум-треков продаются в магазине за кристаллы), на каждой карточке — процедурная обложка (SVG из хэша id и жанра: `entities/track/ui/TrackCover`), жанр и темп, теги механик (смена полос / круги / дроби / слайды / холды) и лучший ранг. Жанр (`genre`) задаётся в `assets-src/tracks.json` и попадает в `ChartFile` и `TrackMeta`. Одна карта на песню: сложность — свойство самой песни, а не выбор в меню.

**v1.4 — открытие треков, трек дня, цели** (`entities/progress`):

- **Открытие.** Первые 5 треков открыты всегда; каждый следующий открывается по порогу звёзд, растущему с позицией: `round((позиция − 4) · 2.2)`, но не выше `N·3 − 6` (171 для 59 треков, `model/unlocks.ts`). Закрытая карточка затемнена, с замком и подписью «нужно ★ N». Флаг `UNLOCK_ALL` в `shared/config/constants.ts` (`false`) и dev-override `?unlock=1` (читается в одном месте — `shared/config/devFlags.ts`) открывают всё. Своя музыка и трек дня открыты всегда.
- **Трек дня.** Детерминированный выбор из каталога по локальной дате (FNV-1a от `YYYY-MM-DD`, `model/daily.ts`), карточка «ТРЕК ДНЯ» закреплена сверху списка. Прохождение (ранг ≥ C, без провала) даёт +1 бонусную ★ раз в день; считается серия дней.
- **Цели.** 8 фиксированных целей (`model/goals.ts`): пройди 5 треков, S на трёх песнях, полное комбо, 20 ★, 10 замедлений, комбо 100, трек дня 3 дня, трек ★6. Считаются из сохранения и счётчиков (спеллы по видам, сыгранные треки, макс. комбо, серия трека дня); выполненная цель один раз даёт награду в ★ (`goalsClaimed`). Панель целей — под шапкой меню (`widgets/goals-panel`), выполнение показывается строкой на экране результата.

**v2.1 — кристаллы и магазин** (`features/play-chart/model/gems.ts`, `entities/progress/model/shop.ts`):

- **Кристаллы в заходе.** Карты не меняются: на старте захода `GameSession` выбирает 6–10 обычных тапов (не раньше 5 с, по одному на равный отрезок песни, детерминированно от seed через `mulberry32`), один из них — большой (5 кристаллов). Нота-кристалл рисуется вращающимся предрендеренным кристаллом с искрящимся шлейфом; попадание (≥ Good) собирает его — кристалл летит к счётчику в HUD, вспышка частиц, «milestone» на повышенной скорости. Промах — кристалл потерян. `PlayResult.crystals`; в обучении кристаллов нет.
- **Кошелёк.** Сохранение v4: `crystals` (баланс), `lifetimeCrystals`, `purchased[]`. Кристаллы зачисляются за любой незавершённый провалом заход (каталог и своя музыка), строка «Кристаллы: +N» на экране результата, баланс — в шапке меню (`widgets/wallet-badge`).
- **Магазин** (`pages/shop`, `widgets/shop-grid`). Трек играбелен, если открыт по звёздам ИЛИ куплен; **премиум** (`premium: true` в `assets-src/tracks.json` → `ChartFile` / `TrackMeta`) открывается только покупкой (и как трек дня — на день). Цена `40 + 15·★`, премиум ×1.5. В магазине — премиум, закрытые по звёздам и уже купленные треки; покупка с подтверждением. На карточке закрытого премиум-трека — цена в кристаллах и «В магазин», у купленного — значок кристалла.

Звёзды: 1 за прохождение (ранг ≥ C), +1 за ранг A, +1 за ранг S. 59 треков → максимум 177 ★ за треки, плюс бонусные за трек дня и цели — они учитываются в общем счётчике и в порогах открытия. Сохранение — `entities/progress` (v3: `tracks[id] = лучший результат` + `counters` + `daily` + `goalsClaimed`; v1 с тремя сложностями и v2 мигрируют, счётчики заполняются из лучших результатов).

### Обучение

Первый запуск: калибровка → обучение (один раз, `settings.tutorialDone`; повторно — кнопка «Обучение» в меню или «Пройти обучение заново» в настройках, где рядом бейдж «Обучение пройдено»). Рукописная карта `public/charts/tutorial.json` (план в долях — `scripts/gen-tutorial.mjs`, `npm run chart:tutorial`; не из анализатора, не в каталоге) на сетке долей Apparatus Overlord — путешествие по числу полос 1 → 2 → 3 → 4 → 5 → 6: одна полоса (тапы по долям «как в Magic Tiles», затем холды) → две (чередование рук, слайды) → три (дроби) → четыре (окно кругов и спелл замедления) → пять (всё вместе, аккорд) → шесть (короткий финал). Каждую секцию открывает переход-морф полос и подпись «Полосы: N» с клавишами `KEY_LABELS[N]` на десктопе и зонами на тач; перед сменой полос ≥ 2 доли тишины, не больше двух вещей одновременно, дроби ≤ 6 ударов/с, слайды только в соседнюю полосу, круги ≥ восьмой друг от друга. Одна полоса — узкая центральная колонка (≤ 220 px), любая клавиша полос попадает в неё, тач-зона — вся нижняя половина. Сценарий в долях — `features/tutorial` (`TUTORIAL_PLAN`, `buildScript`, `captionAt`), подписи над полем — `widgets/tutorial-overlay` (иконка механики и иконка полос, подсказки для клавиш и пальцев, «Отлично!» после первого попадания шага, «Пропустить»). Сердец нет, провала нет, результат не сохраняется.

### Рекорды и онлайн-таблица

`entities/history` хранит до 50 попыток на трек (счёт, точность, ранг, комбо, провал) с трендом точности; карточка трека открывает модалку с спарклайном. Онлайн-таблица (`api/scores.ts`, Upstash Redis REST, топ-100 на трек, лучший результат на ник, rate limit) включается переменными `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` на Vercel; без них секция не показывается. Ник — до 16 символов, спрашивается один раз.

### Экран результата

`GameSession` пишет каждое судейство в `JudgementTimeline` (типизированные массивы, без аллокаций) и отдаёт `PlayResult.timeline` + `duration`. Из них (`entities/score/lib/resultStats`): полоса «где промахи» с секциями полос, график точности и комбо, лучшая серия / первый промах / слабое место (окно 10 с), повтор самых плотных 8 с лучшей серии на мини-поле, карточка 1080×1350 для `navigator.share` или скачивания, текст в буфер обмена.

### Темы и ощущение

Тема трека (`shared/lib/render/themes.ts`): по жанру из карты, иначе детерминированно по id — палитра полос, акцент, свечение, мотив фона. Фон синхронизирован с музыкой: пульс на долях из `chart.beats` (`BeatCursor`), спектр-«скайлайн» из AnalyserNode (один read на кадр, бас из того же буфера). На уровне FX `low` фоновые эффекты и часть частиц отключаются.

### Мобильная версия

Safe-area через `env(safe-area-inset-*)` в CSS-токенах и HUD; тач-зоны во всю ширину с подсветкой нажатой; мультитач — `PointerLanes` (pointercancel = pointerup); подсказка «поверни телефон» с паузой в ландшафте на коротком экране; экономный режим `fxMode` (авто: FPS < 45 три секунды → `low`, один раз); PWA-манифест и иконки. Подробности и чек-лист реального устройства — `docs/mobile-checklist.md`.

### Приложение (PWA)

Service worker `public/sw.js` без библиотек: оболочка прекешируется (список и хеш сборки подставляет `scripts/build-sw.ts`), `/music`, `/charts`, `/sfx`, `/voice`, `/icons` — cache-first с лимитом 200 МБ и вытеснением самых старых записей, `index.html` — network-first. Новая версия ждёт: тост «Доступно обновление — обновить» (`widgets/update-toast`, чистый редьюсер `shared/lib/pwa/updateState.ts`) → `SKIP_WAITING` → `controllerchange` → перезагрузка; во время игры тост не показывается. Баннер «Установить приложение» (`widgets/install-banner`): на Chromium повторяет перехваченный `beforeinstallprompt`, на iOS Safari объясняет «Поделиться → На экран „Домой“»; «Не сейчас» помнится 30 дней, в standalone баннер скрыт. Установленное приложение: тёмный сплэш с логотипом в `index.html` до первого рендера React, запрет зума и жестов (`installStandaloneGuards`), пауза при уходе в фон с живым AudioContext. Иконки PNG рендерятся процедурно и кодируются собственным PNG-энкодером (`npm run assets:icons`). Путь в Google Play — TWA (`docs/android-app.md`, `public/.well-known/assetlinks.json`, `public/privacy.html`).

## 4. Технический стек

```
UI         React 18 + TypeScript strict, Feature-Sliced Design
Рендер     Canvas 2D + offscreen-слой статики + предрендер glow-спрайтов
Аудио      Web Audio API — без библиотек
Анализ     собственный FFT → spectral flux → автокорреляция → генератор карт; Web Worker
Сборка     Vite, vitest, eslint (+ boundaries), GitHub Actions
Состояние  собственный store на useSyncExternalStore, localStorage
Хостинг    Vercel
Рантайм-зависимости: react, react-dom. Всё остальное — свой код.
```

**Почему React, если «ноль зависимостей»:** React отвечает только за экраны-меню. Игровой цикл, аудио, судейство, рендер нот и анализ сигнала — чистый TypeScript в `shared/lib` и `features/play-chart`, и именно они — предмет разговора на собеседовании. Открыв `package.json`, работодатель не увидит `phaser` или `tone.js`.

### Критические технические требования

**1. Единственный источник времени — `audioContext.currentTime`.**

```ts
// shared/lib/audio/Clock.ts
songTime() { return audioNow() - startTime - userOffset; }
```

`requestAnimationFrame` — только для отрисовки. Таймстампы событий ввода (`event.timeStamp`) переводятся в аудиовремя, чтобы компенсировать задержку между нажатием и обработчиком.

**2. Калибровка задержки — при первом запуске.** Метроном 120 BPM планируется look-ahead-планировщиком на аудиочасах; игрок тапает 16 раз; медиана отклонений → `settings.audioOffsetMs`. Ручной слайдер −300…+300 мс в настройках.

**3. Окна попадания.**

```ts
HIT_WINDOWS = { perfect: 0.045, great: 0.090, good: 0.135 } // с; дальше — miss
```

**4. Момент появления ноты.** `approachTime = 1.6 с / scrollSpeed` (1.0–3.0×); `spawn = hitTime − approachTime`, координата `y = hitY − (hitTime − songTime) · hitY / approachTime`.

`notes` — `[t, lane]` тап; `[t, lane, dur]` холд (голова + хвост); `[t, lane, 0, 'slow' | 'heart']` спелл; `[t, lane, dur, 'slide', endLane]` слайд в соседнюю полосу (хвост засчитан, если в момент конца зажата `endLane`); `[t, lane, dur, 'roll', taps]` дробь (`taps` нажатий за `dur`, ≥ ½ — Good, все — Perfect); `[t, lane, 0, 'circle']` круг (нумеруется внутри группы, тап по кругу на экране). `sections` — `[t, laneCount]`, 3–5 полос; без секций — 4. `beats` — доли трекера.

### Автогенератор карт (ключевая фича)

Принцип v1.3: **ноты стоят на реальных ударах музыки** (локальные пики силы удара на сетке 16-х), а не на шаблоне — играешь «по слуху», как будто сам бьёшь по барабанам; шаблоны ритма остались только как справочник для тестов.

1. `decodeAudioData` → `AudioBuffer` → моно-микс 22 050 Гц (в Node — ffmpeg → f32le).
2. STFT: окно Ханна 1024, hop 512, собственный radix-2 FFT.
3. **Spectral flux**: Σ max(0, log(1+10·|X_t|) − log(1+10·|X_{t−1}|)); отдельно по полосам 20–250 / 250–2000 / >2000 Гц; плюс энергия середины (250–2000 Гц) на кадр — для холдов.
4. Онсеты: адаптивный порог (скользящее среднее ±10 кадров × 1.5), локальные максимумы, ≥ 50 мс между ударами.
5. Темп: автокорреляция огибающей flux (60–220 BPM), бонус за кратные лаги, параболическая интерполяция, фолд в 90–180.
6. **Трекер долей** (`BeatTracker.ts`, динамическое программирование Эллиса, как в librosa): доли ставятся на сильные удары *и* держат ровный шаг; Σ score(beat) − tightness · Σ log²(Δt/период). Дрейф от неточного BPM исключён — сетка следует за реальной музыкой. Даунбит — фаза с максимумом басовой энергии.
7. **Сетка**: 16 слотов на такт между соседними долями. На каждый слот: сила удара (0..1, норма по p95), доли полос, `sustain` — сколько слотов подряд середина держит ≥ 50 % энергии.
8. **Динамика**: интенсивность такта 0/1/2 по сглаженной средней силе (квантили q35/q70 с абсолютными порогами).
9. **Фигура фразы (v1.5)**: для каждой 4-тактовой фразы считается профиль ритма — средняя по её тактам сила удара (× буст тихой фразы) на каждом из 16 шагов. Шаги профиля, которые являются локальными пиками и не ниже 40 % от максимума, — это *фигура* («ту ту ТУ»); в интенсивных фразах к ним добавляются соседние шаги ≥ 70 % (пары 16-х «та-ка»). Каждый такт фразы получает ноту на каждом шаге фигуры, где в этом такте реально есть удар (≥ 50 % от профиля и не ниже абсолютного пола 0.05) — фигура повторяется такт за тактом, как в музыке. Шаги ≥ 85 % от максимума — акценты («ТУ»): аккорд из двух нот, если оба пальца свободны, иначе крайняя полоса. Удары вне фигуры добавляются только очень сильные (≥ 85 % от максимума фразы: сбивки, стабы). Приоритет при равной силе: доли > восьмые > 16-е. Лимит нот на такт по интенсивности [3 / 6 / 9] (на 2 полосах ≤ 4, на 3 — ≤ 6), между обычными нотами ≥ восьмая (в интенсивных тактах ≥ 16-я), скользящий потолок 3 / 4 / 4.5 нот/с по интенсивности и 5.5 в припевах энергичных песен. Решения по холдам/слайдам/дробям принимаются на (фраза, шаг), поэтому один и тот же шаг фигуры играется одинаково во всех тактах фразы. Код: `shared/lib/analysis/{bars,phrasePattern,lanePlan,laneAssign,stars}.ts`, дирижёр — `ChartGenerator.composeChart`.
10. **Дроби (roll)**: (а) сбивка — последняя доля/две такта, где звучит *каждая* 16-я и офф-16-е заметно громче, чем в остальном такте; (б) «стрим» — последний такт интенсивной фразы с четырьмя слышимыми восьмыми во второй половине (хотя бы две из них — шаги фигуры), пауза 2 такта; (в) тянущийся басовый звук. Сбивка сильнее тянущейся ноты: звучащий холд обрезается у начала дроби. Сбивки и стримы находятся до плана полос, чтобы смена полос (с её двумя долями тишины) не попадала на них. Нажатий ≤ 6 в секунду: на быстрых песнях дробь укорачивается или остаётся тапами.
11. **Холды и слайды**: нота на слоте с `sustain ≥ 2` и не басовом ударе становится длинной (до 16 слотов, бюджет 3 на такт, шанс выше в тихих частях). Холд ≥ доли с шансом 0.4 становится **слайдом** в соседнюю свободную полосу; на время слайда других нот нет вообще (палец едет — тапать нечем).
12. **Два пальца**: не больше одной длинной ноты (холд / дробь / слайд) одновременно; аккорды (2 ноты) только на сильных долях, когда ничего не зажато и не внутри стрима.
13. **Круги**: старт интенсивной фразы (припев, дроп) открывает окно только кругов: обычные ноты убраны (и за долю до окна), а круг стоит на *каждом* ударе фигуры окна (≥ восьмая между кругами), пока фигура держит ≥ 75 % силы первого такта — 2–4 такта, то есть десятки кругов подряд, если ритм не останавливается. Песни ★ ≥ 6 открывают окно на каждом старте интенсивной фразы, остальные — на 8-тактовых границах; между окнами ≥ 8 тактов полос. Круги рисуются на сетке 3 × 3 по всему полю (обход по номеру), на экране не больше четырёх ближайших. Окно попадания у кругов почти вдвое шире, чем у нот на полосах: 0.09 / 0.18 / 0.28 с (`CIRCLE_HIT_WINDOWS`), а кроме того круг **открыт** всю вторую половину подлёта кольца (`CIRCLE_OPEN_SHARE` = 0.5 от approach, 0.65–1.2 с): любой тап, пока кольцо сжимается, засчитывается минимум как Good; пока круг закрыт, его номер нарисован контуром; с момента открытия диск заполняется цветом от центра и становится полным ровно в момент попадания — по нему и тапают. Режимы не смешиваются.
14. **Полосы**: стримы — «лесенка вверх/вниз», «зигзаг», «трель» (меняются каждый такт); редкие ноты — бас слева, верх справа; правило «≤ 2 подряд в одну полосу» (аккорды и круги считаются). **Секции** 2–6 полос: пулы по интенсивности — тихо [2, 3], средне [3, 4], припев [4, 5, 6]; решение каждые 4 такта в энергичных песнях (средняя интенсивность ≥ 1.2), иначе каждые 8; интро всегда 4; прежнее число полос сохраняется с шансом 0.4 (и всегда после такта со сбивкой). Переход происходит, как только исчезла последняя нота старой секции (до появления новых), перед ним 2 доли тишины.
15. **Спеллы**: с 4-го такта каждые 8 тактов первый обычный тап — спелл: чередуются «замедление» и «сердце».
15b. **Профили сложности** (`Profile` в `ChartGenerator`): `NORMAL` — песня как есть; `EASY` — чтение для новичка: только доли (≥ доля между нотами), 2–4 ноты на такт, ≤ 2 нот/с, без дробей, слайдов, аккордов и 16-х, круги ≥ доля друг от друга и не больше 4 в окне, 3–4 полосы; `MEDIUM` — восьмые, холды и слайды, без дробей и аккордов, до 5 полос, ≤ 3.5 нот/с. `generate-charts` считает обычный рейтинг всех песен, десять самых спокойных (не премиум) переводит в EASY (глава 1, ★1), следующие десять — в MEDIUM (глава 2, ★1–3). Каталог: ★1 ×12, ★2 ×6, ★3 ×2, дальше ★5–9.
16. Звёзды — ощущаемая сложность: `nps·2.3 + share16·2 + max(0, peak − nps)·0.3 + wide·1.2 + special·2.5 + chords·1.5 + tempo·0.6 − 2.2`, где `share16` — доля 16-х промежутков, `peak` — плотнейшие 2 секунды, `wide` — доля песни на ≥ 5 полосах, `special` — доля слайдов/дробей/кругов, `chords` — доля вторых голосов аккордов, `tempo = clamp((bpm − 100) / 80)`. Откалибровано по каталогу: ★3 у самого лёгкого трека, ★9 у самых сложных. Скорость нот — своя у песни: 3.5 доли на подлёт (1.3–2.4 с).

Работает в Web Worker с прогрессом по стадиям (удары → доли → сетка → раскладка). Тот же модуль запускается в Node для встроенных треков — карты игрока и встроенные карты делает один и тот же код.

### Жизни, спеллы, тач-помощь

- **5 сердец**: промах −1, 25 чистых попаданий подряд +1, спелл «сердце» +1 (максимум 5). Ноль сердец — провал, результат не засчитывается, RETRY.
- **Спелл «замедление»**: неоновые песочные часы в кольце; поймал — 6 секунд песни идут в 0.72× скорости *вместе с музыкой* (playbackRate + «плёночный» lowpass, вход 0.35 с, выход 0.5 с), часы и судейство идут по тому же замедленному времени, ритм не сбивается; индикатор над полем.
- **Автоподстройка задержки**: медиана последних 40 ошибок тайминга по половине вносится в оффсет (до ±80 мс); после трека с ≥ 60 попаданиями сохраняется в настройки.
- **Тач-помощь** (по умолчанию на телефоне, выключается в настройках): нажатие до 0.4 с *раньше* ноты «заряжает» её, и она засчитывается как Great, когда доходит до линии. На ПК тайминг строгий.

### Спецэффекты

Предрендер + пулы, без аллокаций в кадре: кольцо на Perfect, шлейф за нотой, подпрыгивание рецептора на каждом нажатии, «+очки» под судейством, искры из рецептора во время холда/дроби/слайда, счётчик «2/4» над дробью, полосатое тело дроби и наклонное тело слайда с шевронами и маркером пальца, пунктирная связка между соседними кругами, ударная волна и бегущий баннер «N COMBO» на порогах комбо, дрожь и «прыжок» цифры комбо от 20, взрыв частиц и тряска при потере сердца, «удар камеры» (зум 1.2 %) и подсветка поля на басовых ударах *самого трека* (AnalyserNode, а не сетка), смена числа полос — разделители и рецепторы физически съезжаются/разъезжаются с лёгким перелётом и световыми шлейфами, большая цифра нового числа полос, вспышка всех рецепторов в момент фиксации.

## 5. Тесты

`vitest`, окружение node, без DOM — движок спроектирован так, чтобы тестироваться без браузера:

- `Clock` — дрейф, offset, пауза/резюм
- `Scoring` / `judgeDelta` — окна, точность, ранги, «до S не хватило N»
- `NoteManager` — судейство таймингов, холды, авто-мисс, курсоры
- `OnsetDetector` — синтетический сигнал: ≥ 90 % онсетов в ±30 мс без потока ложных
- `BpmEstimator` — 128 BPM ± 2
- `ChartGenerator` — квантование, кап плотности, «≤ 2 подряд», монотонные звёзды, детерминизм
- `SaveData` — миграции, звёзды, слияние результатов
- `Calibration` — медиана против выброса
- `ParticlePool` / `ScreenShake` — ёмкость, амплитуда ≤ 4 px
- `unlocks` / `daily` / `goals` — пороги открытия, детерминированный трек дня, прогресс и награды целей, миграция сохранения v2 → v3
- `tutorial` — сценарий по долям и валидация рукописной карты (сетка 30 мс, дроби ≤ 6/с, слайды в соседнюю полосу, каждая нота внутри шага своей механики)
- `resultStats` / `JudgementTimeline` — серии, окно промахов, кривые точности и комбо, выбор окна повтора
- `PointerLanes` / `LowFpsDetector` / `layout` — мультитач, FPS-сторож, тач-зоны в портрете и ландшафте
- `themes` / `spectrum` / `cover` — цвет GOOD на любой палитре, бас из спектра, детерминизм обложек
- `History` — кап 50 попыток на трек, порядок «новые сверху», лучший результат, тренд точности
- `api/_lib/scores` — валидация тела запроса, ранжирование, «лучший на ник», rate limit; `shared/api/leaderboard` — клиент никогда не бросает (mock fetch)
