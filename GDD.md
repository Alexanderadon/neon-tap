## 0. Музыка: почему в игре нет чужих хитов

Нарушение авторского права возникает в момент **воспроизведения и распространения**, а не получения прибыли. Некоммерческое использование влияет на размер компенсации, а не на законность. Практические последствия для хостинга:

| Где хостится | Что произойдёт с лицензионными треками |
|---|---|
| GitHub Pages / Vercel | DMCA takedown → проект отключают, аккаунт получает страйк |
| Резюме | **мёртвая ссылка** — худший исход для портфолио |

Piano Tiles-клоны с лицензионными треками снимают регулярно; osu! держит отдельный DMCA-процесс; Beat Saber и Guitar Hero покупали лицензии. Тимлид, глядящий портфолио, знает про DMCA — игра с ворованными треками читается как минус.

### Двухслойная модель контента

1. **Встроенный саундтрек** — 16 треков под **CC0** (public domain) с OpenGameArt: synthwave, EDM, drum&bass, hardstyle, techno. Реестр: `assets-src/tracks.json`, отчёт по лицензиям: `public/music/LICENSES.md`.
2. **«Своя музыка»** — игрок кидает MP3/OGG/WAV, движок сам генерирует карту через onset-detection в Web Audio API. Файл не покидает браузер, ничего не распространяется → нарушения нет.

Второй пункт важнее первого: автогенерация карт из произвольного аудио — единственная фича, которую нельзя списать с туториала. Именно она в первом абзаце README.

### Почему OpenGameArt, а не Pixabay

Pixabay требует логин для скачивания и не отдаёт музыку через API — пайплайн нельзя воспроизвести скриптом. OpenGameArt даёт прямые ссылки и CC0-фильтр; каждый файл в репозитории восстанавливается командой `npm run assets:music` из реестра.

## 1. Что даёт зависимость — исследование → механики

| Рычаг | Механика | Где в коде |
|---|---|---|
| **Комбо и страх его потерять** (loss aversion) | Комбо крупно, шрифт `32 + min(combo, 500)·0.06`; цвета на порогах 50 → cyan, 100 → фиолетовый, 250 → золото, 500 → белый с пульсацией. При промахе комбо разлетается частицами + звук «стекло». | `features/play-chart/lib/Renderer.ts`, `shared/lib/audio/sfx.ts` |
| **Промах ломает музыку** | Lowpass 800 Гц на мастер-канал + −40 % громкости на 250 мс. Наказание слышно, а не только видно. | `AudioEngine.missEffect()` |
| **Near-miss** | Экран результатов: разбивка Perfect/Great/Good/Miss и «до ранга S не хватило N нот». RETRY — крупнейшая кнопка, в фокусе. | `entities/score/notesToReach`, `widgets/result-breakdown` |
| **Нулевое трение рестарта** | Трек в памяти (`AudioBuffer`); рестарт = сброс индексов + `source.start()`. Хоткей `R`. Переходы ≤ 200 мс. | `GameSession.restart()` |
| **Flow** | Звёзды 1–10 на песню (плотность, пики, доля механик, темп); плоский список от лёгких к сложным, лучший ранг на карточке. | `ChartGenerator.rateStars`, `widgets/track-list` |
| **Незакрытый прогресс** (Зейгарник) | Счётчик «★ N / 63» над списком и ранг на каждой карточке — что не закрыто, видно сразу. | `widgets/track-list` |
| **Juice** | Вспышка полосы 80 мс, пул 300 частиц без аллокаций, shake ≤ 4 px только на промахах и порогах комбо, пульсация фона в такт, предрендеренное свечение (не `shadowBlur` в кадре). | `shared/lib/render/*` |

## 3. Концепт

**Название:** NEON TAP
**Жанр:** ритм-игра на 3–5 полос, браузер, desktop + mobile
**Сессия:** 90–150 секунд на трек
**Управление:** `D F J K` при 4 полосах; 3 → `D F J`, 5 → `D F G/H J K`; круги — тап по кругу на экране или `Space`; на мобиле — тач-зоны по числу полос в нижней половине экрана, слайд — ведёшь палец в соседнюю зону
**Стиль:** тёмный фон, неоновые полосы (cyan / magenta / lime / orange / violet), виньетка, полосы физически разъезжаются и сливаются при смене их числа

### Прогрессия

**v1.3:** миров нет. Один плоский список из 59 треков, отсортированный по звёздам песни (★2–9 во встроенном контенте; 6 премиум-треков продаются в магазине за кристаллы), на каждой карточке — процедурная обложка (SVG из хэша id и жанра: `entities/track/ui/TrackCover`), жанр и темп, теги механик (смена полос / круги / дроби / слайды / холды) и лучший ранг. Жанр (`genre`) задаётся в `assets-src/tracks.json` и попадает в `ChartFile` и `TrackMeta`. Одна карта на песню: сложность — свойство самой песни, а не выбор в меню.

**v1.4 — открытие треков, трек дня, цели** (`entities/progress`):

- **Открытие.** Первые 5 треков открыты всегда; каждый следующий открывается по порогу звёзд, растущему с позицией: `round((позиция − 4) · 2.2)`, но не выше `N·3 − 6` (171 для 59 треков, `model/unlocks.ts`). Закрытая карточка затемнена, с замком и подписью «нужно ★ N». Флаг `UNLOCK_ALL` в `shared/config/constants.ts` (`false`) и dev-override `?unlock=1` (читается в одном месте — `shared/config/devFlags.ts`) открывают всё. Своя музыка и трек дня открыты всегда.
- **Трек дня.** Детерминированный выбор из каталога по локальной дате (FNV-1a от `YYYY-MM-DD`, `model/daily.ts`), карточка «ТРЕК ДНЯ» закреплена сверху списка. Прохождение (ранг ≥ C, без провала) даёт +1 бонусную ★ раз в день; считается серия дней.
- **Цели.** 8 фиксированных целей (`model/goals.ts`): пройди 5 треков, S на трёх песнях, полное комбо, 20 ★, 10 замедлений, комбо 100, трек дня 3 дня, трек ★6. Считаются из сохранения и счётчиков (спеллы по видам, сыгранные треки, макс. комбо, серия трека дня); выполненная цель один раз даёт награду в ★ (`goalsClaimed`). Панель целей — под шапкой меню (`widgets/goals-panel`), выполнение показывается строкой на экране результата.

**v2.1 — кристаллы и магазин** (`features/play-chart/model/gems.ts`, `entities/progress/model/shop.ts`):

- **Кристаллы в заходе.** Карты не меняются: на старте захода `GameSession` выбирает 6–10 обычных тапов (не раньше 5 с, по одному на равный отрезок песни, детерминированно от seed через `mulberry32`), один из них — большой (5 кристаллов). Нота-кристалл рисуется вращающимся предрендеренным кристаллом с искрящимся шлейфом; попадание (≥ Good) собирает его — кристалл летит к счётчику в HUD, вспышка частиц, «milestone» на повышенной скорости. Промах — кристалл потерян. `PlayResult.crystals`; в обучении кристаллов нет.
- **Кошелёк.** Сохранение v4: `crystals` (баланс), `lifetimeCrystals`, `purchased[]`. Кристаллы зачисляются за любой незавершённый провалом заход (каталог и своя музыка), строка «Кристаллы: +N» на экране результата, баланс — в шапке меню (`widgets/wallet-badge`).
- **Магазин** (`pages/shop`, `widgets/shop-grid`). Трек играбелен, если открыт по звёздам ИЛИ куплен; **премиум** (`premium: true` в `assets-src/tracks.json` → `ChartFile` / `TrackMeta`) открывается только покупкой (и как трек дня — на день). Цена `40 + 15·★`, премиум ×1.5. В магазине — премиум, закрытые по звёздам и уже купленные треки; покупка с подтверждением. На карточке закрытого премиум-трека — цена в кристаллах и «В магазин», у купленного — значок кристалла.

Звёзды (v2.3): по одной за каждый пройденный уровень песни — см. «Уровни и звёзды»; старые сохранения без поля `stars` читаются по рангу (C = 1, A = 2, S = 3). 59 треков → максимум 177 ★ за треки, плюс бонусные за трек дня и цели — они учитываются в общем счётчике и в порогах открытия. Сохранение — `entities/progress` (v3: `tracks[id] = лучший результат` + `counters` + `daily` + `goalsClaimed`; v1 с тремя сложностями и v2 мигрируют, счётчики заполняются из лучших результатов).

### Обучение

Задержка вывода звука устройства (`AudioContext.outputLatency + baseLatency`; наушники Bluetooth добавляют до 250 мс) вычитается автоматически и обновляется каждый кадр (`Clock.deviceLatency`): плитка касается линии в тот момент, когда игрок *слышит* удар, а калибровка измеряет только остаток (реакция, тач). Первый запуск: калибровка → обучение (один раз, `settings.tutorialDone`; повторно — кнопка «Обучение» в меню или «Пройти обучение заново» в настройках, где рядом бейдж «Обучение пройдено»). Рукописная карта `public/charts/tutorial.json` (план в долях — `scripts/gen-tutorial.mjs`, `npm run chart:tutorial`; не из анализатора, не в каталоге) на сетке долей Apparatus Overlord — путешествие по числу полос 1 → 2 → 3 → 4 → 5 → 6: одна полоса (тапы по долям «как в Magic Tiles», затем холды) → две (чередование рук, слайды) → три (дроби) → четыре (окно кругов и спелл замедления) → пять (всё вместе, аккорд) → шесть (короткий финал). Каждую секцию открывает переход-морф полос и подпись «Полосы: N» с клавишами `KEY_LABELS[N]` на десктопе и зонами на тач; перед сменой полос ≥ 2 доли тишины, не больше двух вещей одновременно, дроби ≤ 6 ударов/с, слайды только в соседнюю полосу, круги ≥ восьмой друг от друга. Одна полоса — узкая центральная колонка (≤ 220 px), любая клавиша полос попадает в неё, тач-зона — вся нижняя половина. Сценарий в долях — `features/tutorial` (`TUTORIAL_PLAN`, `buildScript`, `captionAt`), подписи над полем — `widgets/tutorial-overlay` (иконка механики и иконка полос, подсказки для клавиш и пальцев, «Отлично!» после первого попадания шага, «Пропустить»). Сердец нет, провала нет, результат не сохраняется.

### Рекорды и онлайн-таблица

`entities/history` хранит до 50 попыток на трек (счёт, точность, ранг, комбо, провал) с трендом точности; карточка трека открывает модалку с спарклайном. Онлайн-таблица (`api/scores.ts`, Upstash Redis REST, топ-100 на трек, лучший результат на ник, rate limit) включается переменными `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` на Vercel; без них секция не показывается. Ник — до 16 символов, спрашивается один раз.

### Радио колоды (v2.6)

В меню тихо играет трек, на котором стоит колода: с трети песни, по кругу, на 12 % громкости музыки (`widgets/track-list/model/useDeckRadio.ts`, `AudioEngine.ambient / stopAmbient`), с плавным входом и выходом; при листании песня меняется, когда колода успокоилась на карте (450 мс), декодированные песни кэшируются (4). Пока звук не разблокирован жестом — тишина; запуск игры, превью в магазине или уход с меню гасят радио. На центральной карте — блик (`.deck-sheen`): мягкий диагональный свет, медленно плывущий по обложке, его сила (`--radio`, по басу из анализатора, ~30 раз в секунду) дышит с музыкой и равна нулю в тишине. Магазин ужат: карточка 335 × 72, заголовок 15, фишки 26, цена 16, диск 32. Жест «назад» страницы меню спит, пока открыт диалог (ник, аватар, оффер) — раньше закрытие диалога свайпом выбрасывало на главную.

### Обложки-картинки (v2.6)

У трека может быть настоящая обложка: квадратная картинка в `assets-src/covers-raw/<id>.png|jpg|webp` → `npm run assets:covers` (Pillow, `tools/covers/make-cover.py`) → `public/covers/<id>.webp` 730 × 1050 (карта колоды 292 × 420 в 2.5×): картинка во всю ширину посередине, сверху и снизу её же край, отражённый, размытый и затемнённый к краю карты, со швом-растушёвкой 64 px — карта читается как одна картинка в тех же цветах. В каталоге появляется поле `cover` (его же ставит `generate-charts`, глядя в `public/covers`); `TrackCover` тогда рисует `<img>` с `object-fit: cover` (квадратные места — магазин, результат, дуэль, круг паузы — показывают середину, то есть саму картинку; карта колоды — целиком с полями), сцена `CoverScene` берёт цветовую вуаль из картинки, а не из процедурного арта. Без картинки — прежний процедурный арт. Нужный размер исходника: квадрат от 1000 × 1000 (лучше 1024–1500), главное — в центре, поля рисуем сами. Обложки кэширует SW как медиа (`/covers/`).

### Паки треков (v2.6)

Каталог делится на главы по 10 треков (`entities/track/model/chapters.ts`: `chaptersOf`, `chapterAt`, `chapterTitle`), а после них идут **паки** — именованные главы из треков с полем `pack` в `assets-src/tracks.json` (`generate-charts` ставит их после основного каталога, каждый пак — своя группа в опубликованном порядке). Ярлык над колодой, строка паузы и результата показывают имя пака (`packNames` в i18n: `rock` — «Рок-пак») вместо «Глава N». Все треки пака рисуют одну обложку (`coverSpec` сеет арт от id пака; настоящая картинка пака — позже). Открытие пока общее — по позиции в каталоге; какие паки платные, решается отдельно. Первый пак — рок с Free Music Archive (три трека **CC BY 4.0**: Mr Smith «Call of the North», «Naomi», Alex Morgan «Grunge Nostalgia»; треки BY-ND / BY-NC-ND не берём — игра коммерческая и ускоряет песню на уровнях). Конвейер тот же: запись в `tracks.json` → `assets:fetch-music` (для FMA качает по `playbackUrl` страницы и сверяет лицензию) → `assets:music -- id…` → `tools/demucs/separate-all.sh id…` → `assets:charts` → `assets:licenses`.

### Аватары

Вместо первой буквы ника игрок может выбрать одного из двенадцати персонажей: `cat` — Кот в наушниках, `fox` — Лис-диджей, `robot` — Робот, `astronaut` — Космонавт, `panda` — Панда с бумбоксом, `alien` — Пришелец, `dragon` — Дракончик, `owl` — Сова в очках, `shark` — Акула, `bunny` — Зайка в кепке, `ghost` — Призрак, `dino` — Дино с ирокезом. Каталог — `entities/avatar` (ids и порядок — `shared/config/avatars.ts`, имена — словарь `avatarNames`), выбор хранится в `settings.avatar` (`''` = буква; незнакомый id при загрузке сбрасывается в букву). Выбор — в профиле, строка «Аватар» → окно поверх экрана (сетка 4 × 3 кружков 56 px с именами, выбранный обведён циан, «Готово» закрывает, «Буква» возвращает букву) и на экране знакомства по тапу на большой аватар («выбери аватар»). Показывается везде, где стоит аватар игрока: шапка, карточка профиля, диалог ника, настройки, строка «я» в рекордах; в дуэлях id уходит вместе с забегом (`avatar` в `DuelRun`), и друг видит аватар хозяина на экране вызова, а хозяин — аватары ответивших. **Арт:** файлы `public/avatars/<id>.webp` (например `public/avatars/cat.webp`), квадрат, персонаж по центру, поле обрезается в круг (`object-fit: cover`), фон — свой (сфера под ним тёмная), рекомендуемый размер 256 × 256. Пока файла нет, рисуется процедурная заглушка (`AvatarEmblem`: глянцевая сфера в акцентном цвете персонажа + силуэт-эмблема); наличие файла проверяется один раз за сессию загрузкой `Image()` (`artCache`), так что достаточно положить файлы в папку — код менять не нужно.

### Экран результата

`GameSession` пишет каждое судейство в `JudgementTimeline` (типизированные массивы, без аллокаций) и отдаёт `PlayResult.timeline` + `duration`. Из них (`entities/score/lib/resultStats`): полоса «где промахи» с секциями полос, график точности и комбо, лучшая серия / первый промах / слабое место (окно 10 с), повтор самых плотных 8 с лучшей серии на мини-поле, карточка 1080×1350 для `navigator.share` или скачивания, текст в буфер обмена.

### Темы и ощущение

Тема трека (`shared/lib/render/themes.ts`): по жанру из карты, иначе детерминированно по id — палитра полос, акцент, свечение, мотив фона. Фон синхронизирован с музыкой: пульс на долях из `chart.beats` (`BeatCursor`), спектр-«скайлайн» из AnalyserNode (один read на кадр, бас из того же буфера). На уровне FX `low` фоновые эффекты и часть частиц отключаются.

### Дизайн-система v3

Источник истины — `.tmp/ux/spec.md` и `.tmp/ux/final.html` (главный экран и результат), пакеты экранов `.tmp/ux/screens-*.html`. Одна колонка 335 px в полях 20 (в приложении `min(100%, 335px)` по центру, safe-area учитывается), одинаковая шапка на всех экранах вне игры, нижняя зона из ряда кнопок-объектов и главной кнопки. ### Ранги

|---|---|
| 100 % | SS |

Засчитан ли заход, решают не ранг, а звёзды: 0 звёзд = провал.

### Уровни и звёзды (v2.3)

Один заход — это песня до трёх раз подряд, каждый раз быстрее (`features/play-chart/model/levels.ts`: скорости 1 → 1.12 → 1.2; ускоряются и музыка, и плитки — `AudioBufferSourceNode.playbackRate` вместе с `Clock`, задержка вывода и калибровка масштабируются на скорость). Уровень пройден, если дожил до конца, — это и есть звезда. Между уровнями игра не прерывается: хвост песни медленно затухает (`AudioEngine.fadeOut`, 1.8 с), в центре поля вспыхивает золотая звезда с надписью «Звезда! Быстрее на 12 %» и улетает в свой слот в HUD (`Renderer.starEarned`, 2.4 с), затем отсчёт нового уровня и песня медленно нарастает с нуля (`fadeIn`, 2 с). Сердца доливаются до пяти (золотые остаются), спеллы и гемы раздаются заново, счёт, комбо, кристаллы и лента судейств идут насквозь (`PlayResult.duration` = длина песни × уровни). Спелл замедления теперь относителен скорости уровня. Кончились сердца на 2-м или 3-м уровне — «СТОП, звёзд заработано: N», заход засчитан с этими звёздами; провал только на первом. `PlayResult.stars`/`level`, `BestResult.stars` (в сохранении держится максимум), `starsForTrack` читает поле, `mergeResult` никогда не понижает. HUD: три звезды под кнопкой паузы (заработанные горят, текущая дышит). Экран результата: три больших звезды вылетают по очереди с чаймом каждая, ранг ушёл в ряд цифр; карточки колоды показывают заработанные звёзды крупно (`shared/ui/Stars` — SVG-звезда с гранью и свечением, одна на весь интерфейс). В обучении уровней нет. Сложность песни — не звезда, а огонёк с числом (`shared/ui/Difficulty`), цвет по ярусу: 1–2 лайм, 3–4 циан, 5–6 жёлтый, 7–8 оранжевый, 9–10 красный; звезда в интерфейсе теперь значит только заработанное.

### Критические технические требования

**1. Единственный источник времени — `audioContext.currentTime`.**

```ts
// shared/lib/audio/Clock.ts
songTime() { return audioNow() - startTime - userOffset; }
```

`requestAnimationFrame` — только для отрисовки. Таймстампы событий ввода (`event.timeStamp`) переводятся в аудиовремя, чтобы компенсировать задержку между нажатием и обработчиком.

**2. Калибровка задержки — при первом запуске.** Метроном 120 BPM планируется look-ahead-планировщиком на аудиочасах; игрок тапает 16 раз; медиана отклонений → `settings.audioOffsetMs`. Ручной слайдер −300…+300 мс в настройках.

**3. Окна попадания.**

```ts
HIT_WINDOWS = { perfect: 0.05, great: 0.1, good: 0.15 } // реальных секунд; дальше — miss
```

Окна — реакция игрока, то есть реальные секунды: на ускоренных уровнях (×1.12, ×1.2) они умножаются на скорость песни (`NoteManager.timeScale`), иначе третий уровень молча сжимал бы Good до 125 мс, а Perfect до 42 мс. **Длинные ноты (v2.4):** если голова попала, хвост никогда не промах — дожал до конца (палец на месте) → Perfect, отпустил раньше → Good; дробь — все удары Perfect, половина — Great, меньше — Good; слайд без пальца в конечной полосе — Good. Промах только у нетронутой длинной ноты (голова и хвост, одно сердце).

**4. Момент появления ноты.** `approachTime = 1.6 с / scrollSpeed` (1.0–3.0×); `spawn = hitTime − approachTime`, координата `y = hitY − (hitTime − songTime) · hitY / approachTime`.

### Генератор карт v3 — бюджет по звёздам (2026-09-16)

Переписан после разбора (план и замеры: `.tmp/gen/plan.md`, `stats.md`, `listen.md`). Раньше «то попадает в бит, то каша»: плитки ставились на всё громкое в спектре, разрешались пары шестнадцатых (89 мс на ×1.2), плотность ограничивалась средним по песне, а уровень проигрывается в худшие 8 секунд; звёзды считались после и ни на что не влияли. Теперь **сначала выбирается звезда песни (★1–6, не выше: глава 1 — ★1–2, глава 2 — ★3–4, остальное и паки — ★2–6 по энергии песни; `chart.stars` / `chart.rolls` в `tracks.json` — ручное переопределение), и под неё в `budget.ts` есть таблица «что можно»**: минимальный зазор между плитками, плиток в такте и в любые 1/4/8 секунд (всё в реальном времени ×1.2), холды/слайды/дроби/аккорды/круги на фразу, полосы 3–5. Плитки — только на слышимые удары (`aud`: attack-gate, «de-smear» — пик микса, присутствующие стемы ≥ 15 % энергии самого громкого; утечки стемов не звучат). Одна фигура на 4-тактовую фразу (`figure.ts`: пики профиля с бонусом сетки, доля с `aud ≥ 0.8` всегда в фигуре, инерция фигуры между фразами одного уровня), такты повторяют фигуру там, где она звучит; при перегрузе окна убирается **целый шаг фигуры** во всей фразе, а не случайные плитки. Уровни фраз 0/1/2 — по квантилям песни с гистерезисом. Холды ≥ доли только по кольцу энергии инструмента (без «огрызков»), дроби на барабанных стримах (≥ 0,7 с, 3–4 нажатия, ≤ 5/с), аккорды с ★5 и ≤ 1 на такт, круги ≤ 3 окна на песню, ≤ 4 на такт и никогда на первом дропе, спиннеры на реальном провале энергии; полосы блоками по 8 тактов, секция ≥ 16 тактов. Звёзды — проверка: `rateStars` = наименьшая ★, чей бюджет держит карту; `generate-charts` не выпускает карту, если она не играбельна двумя пальцами на ×1.2 (`assertPlayable`), выше ★6 или выше своей цели. Темп: чтение выше 175 BPM складывается вдвое (`SongAnalyzer`), чтобы четверти не читались как восьмые. Каталог после пересборки: ★1 ×1, ★2 ×9, ★3 ×3, ★4 ×14, ★5 ×14, ★6 ×3; средняя плотность 1,6 плитки/с, попадание в долю 94 %.

### Автогенератор карт (ключевая фича)

Принцип v1.3: **ноты стоят на реальных ударах музыки** (локальные пики силы удара на сетке 16-х), а не на шаблоне — играешь «по слуху», как будто сам бьёшь по барабанам; шаблоны ритма остались только как справочник для тестов.

1. `decodeAudioData` → `AudioBuffer` → моно-микс 22 050 Гц (в Node — ffmpeg → f32le).
2. STFT: окно Ханна 1024, hop 512, собственный radix-2 FFT.
3. **Spectral flux**: Σ max(0, log(1+10·|X_t|) − log(1+10·|X_{t−1}|)); отдельно по полосам 20–250 / 250–2000 / >2000 Гц; плюс энергия середины (250–2000 Гц) на кадр — для холдов.
4. Онсеты: адаптивный порог (скользящее среднее ±10 кадров × 1.5), локальные максимумы, ≥ 50 мс между ударами.
5. Темп: автокорреляция огибающей flux (60–220 BPM), бонус за кратные лаги, параболическая интерполяция, фолд в 90–180.
6. **Трекер долей** (`BeatTracker.ts`, динамическое программирование Эллиса, как в librosa): доли ставятся на сильные удары *и* держат ровный шаг; Σ score(beat) − tightness · Σ log²(Δt/период). Дрейф от неточного BPM исключён — сетка следует за реальной музыкой. Даунбит — фаза с максимумом басовой энергии.
7. **Сетка**: 16 слотов на такт между соседними долями. На каждый слот: сила удара (0..1, норма по p95), доли полос, `sustain` — сколько слотов подряд середина держит ≥ 50 % энергии.
8. **Динамика**: интенсивность такта 0/1/2 по сглаженной средней силе (квантили q35/q70 с абсолютными порогами).
9. **Фигура фразы (v1.5)**: для каждой 4-тактовой фразы считается профиль ритма — средняя по её тактам сила удара (× буст тихой фразы) на каждом из 16 шагов. Шаги профиля, которые являются локальными пиками и не ниже 40 % от максимума, — это *фигура* («ту ту ТУ»); в интенсивных фразах к ним добавляются соседние шаги ≥ 70 % (пары 16-х «та-ка»). Каждый такт фразы получает ноту на каждом шаге фигуры, где в этом такте реально есть удар (≥ 50 % от профиля и не ниже абсолютного пола 0.05) — фигура повторяется такт за тактом, как в музыке. Шаги ≥ 85 % от максимума — акценты («ТУ»): аккорд из двух нот, если оба пальца свободны, иначе крайняя полоса. Удары вне фигуры добавляются только очень сильные (≥ 85 % от максимума фразы: сбивки, стабы). Приоритет при равной силе: доли > восьмые > 16-е. Лимит нот на такт по интенсивности [3 / 6 / 9] (на 2 полосах ≤ 4, на 3 — ≤ 6), между обычными нотами ≥ восьмая (в интенсивных тактах ≥ 16-я), скользящий потолок 3 / 4 / 4.5 нот/с по интенсивности и 5.5 в припевах энергичных песен. Решения по холдам/слайдам/дробям принимаются на (фраза, шаг), поэтому один и тот же шаг фигуры играется одинаково во всех тактах фразы. Код: `shared/lib/analysis/{bars,phrasePattern,lanePlan,laneAssign,stars}.ts`, дирижёр — `ChartGenerator.composeChart`.
10. **Дроби (roll)**: (а) сбивка — последняя доля/две такта, где звучит *каждая* 16-я и офф-16-е заметно громче, чем в остальном такте; (б) «стрим» — последний такт интенсивной фразы с четырьмя слышимыми восьмыми во второй половине (хотя бы две из них — шаги фигуры), пауза 2 такта; (в) тянущийся басовый звук. Сбивка сильнее тянущейся ноты: звучащий холд обрезается у начала дроби. Сбивки и стримы находятся до плана полос, чтобы смена полос (с её двумя долями тишины) не попадала на них. Нажатий ≤ 6 в секунду: на быстрых песнях дробь укорачивается или остаётся тапами.
11. **Холды и слайды**: нота на слоте с `sustain ≥ 2` и не басовом ударе становится длинной (до 16 слотов, бюджет 3 на такт, шанс выше в тихих частях). Холд ≥ доли с шансом 0.4 становится **слайдом** в соседнюю свободную полосу; на время слайда других нот нет вообще (палец едет — тапать нечем).
12. **Два пальца**: не больше одной длинной ноты (холд / дробь / слайд) одновременно; аккорды (2 ноты) только на сильных долях, когда ничего не зажато и не внутри стрима.
13. **Круги**: старт интенсивной фразы (припев, дроп) открывает окно только кругов: обычные ноты убраны (и за долю до окна), а круг стоит на *каждом* ударе фигуры окна (≥ восьмая между кругами), пока фигура держит ≥ 75 % силы первого такта — 2–4 такта, то есть десятки кругов подряд, если ритм не останавливается. Песни ★ ≥ 6 открывают окно на каждом старте интенсивной фразы, остальные — на 8-тактовых границах; между окнами ≥ 8 тактов полос. Круги рисуются на сетке 3 × 3 по всему полю (обход по номеру), на экране не больше четырёх ближайших. Окно попадания у кругов почти вдвое шире, чем у нот на полосах: 0.09 / 0.18 / 0.28 с (`CIRCLE_HIT_WINDOWS`), а кроме того круг **открыт** всю вторую половину подлёта кольца (`CIRCLE_OPEN_SHARE` = 0.5 от approach, 0.65–1.2 с): любой тап, пока кольцо сжимается, засчитывается минимум как Good; пока круг закрыт, его номер нарисован контуром; с момента открытия диск заполняется цветом от центра и становится полным ровно в момент попадания — по нему и тапают. Режимы не смешиваются.
14. **Полосы**: стримы — «лесенка вверх/вниз», «зигзаг», «трель» (меняются каждый такт); редкие ноты — бас слева, верх справа; правило «≤ 2 подряд в одну полосу» (аккорды и круги считаются). **Секции** 2–6 полос: пулы по интенсивности — тихо [2, 3], средне [3, 4], припев [4, 5, 6]; решение каждые 4 такта в энергичных песнях (средняя интенсивность ≥ 1.2), иначе каждые 8; интро всегда 4; прежнее число полос сохраняется с шансом 0.4 (и всегда после такта со сбивкой). Переход происходит, как только исчезла последняя нота старой секции (до появления новых), перед ним 2 доли тишины.
15. **Спеллы**: с 4-го такта каждые 8 тактов первый обычный тап — спелл. В профиле NORMAL чередуются «замедление» и «сердце»; в EASY и MEDIUM (главы 1–2) только «сердце»; кроме того, на любой карте ниже ★7 замедление заменяется сердцем после расчёта рейтинга (`SLOW_FROM_STARS`) — замедление живёт только на сложных песнях.
15b. **Профили сложности** (`Profile` в `ChartGenerator`): `NORMAL` — песня как есть; `EASY` — чтение для новичка: только доли (≥ доля между нотами), 2–4 ноты на такт, ≤ 2 нот/с, без дробей, слайдов, аккордов и 16-х, круги ≥ доля друг от друга и не больше 4 в окне, 3–4 полосы; `MEDIUM` — восьмые, холды и слайды, без дробей и аккордов, до 5 полос, ≤ 3.5 нот/с. `generate-charts` считает обычный рейтинг всех песен, десять самых спокойных (не премиум) переводит в EASY (глава 1, ★1), следующие десять — в MEDIUM (глава 2, ★1–3). Каталог: ★1 ×12, ★2 ×6, ★3 ×2, дальше ★5–9.
16. Звёзды — ощущаемая сложность: `nps·1.6 + share16·2 + max(0, peak − nps)·0.3 + wide·1.2 + special·2.5 + chords·1.5 + tempo·0.6 − 2.0`, где `share16` — доля 16-х промежутков, `peak` — плотнейшие 2 секунды, `wide` — доля песни на ≥ 5 полосах, `special` — доля слайдов/дробей/кругов, `chords` — доля вторых голосов аккордов, `tempo = clamp((bpm − 100) / 80)`. Откалибровано под поток ударов: около ★3 при 2 нотах/с, ★6 при 4, ★9–10 при 5,5. Скорость нот — своя у песни: 3.5 доли на подлёт (1.3–2.4 с).

Работает в Web Worker с прогрессом по стадиям (удары → доли → сетка → раскладка). Тот же модуль запускается в Node для встроенных треков — карты игрока и встроенные карты делает один и тот же код.

### Плитки по звукам песни: поток нажатий (v2.1)

Правило одно: **плитка стоит там, где слышен удар.** Каждый такт читается сам по себе (`soundSteps`): удар — локальный пик силы онсета (или почти пик: «та-ка» шестнадцатые считаются двумя ударами, `PEAK_TOLERANCE`), не тише 35 % самого громкого удара такта. Никакой усреднённой на 4 такта фигуры, никаких лимитов по «громкости» такта: тихий куплет оставляет все свои удары, действует только потолок профиля (NORMAL 9 нот на такт, 5,5 в секунду). Тап **ничего не меняет в звуке** — песня играет как есть, игрок идёт по её ударам потоком.

Стемы Demucs (`stem-drums / bass / other / vocals.mp3`, лежат на D, в сборку не попадают; `bash tools/demucs/separate-all.sh`, затем `npm run assets:charts`) плитки не двигают, а добавляют то, что микс слышит хуже, и решают форму ноты:

- **Каждая нота, каждый бас.** Удар баса, слог голоса, нота лида со своей мягкой атакой (`STEM_HIT_WEIGHT` 0,8 от силы онсета стема) входят в набор ударов такта наравне с ударами микса.
- **Холд = звук тянется и никто не бьёт.** `soundSustain`: инструмент (голос, лид, бас — барабаны не тянутся) после удара держит энергию ≥ 45 % от удара и не ниже 20 % от своих громких моментов, и нового его удара нет. Не меньше бита — холд, но только до следующего слышимого удара песни: «ту-ДУН-дун-дун» под тянущимся синтом — это тапы, а не холд.
- **Аккорд = два инструмента бьют вместе** (оба ≥ 0,6) на акценте.
- **Полосы меняются, когда меняется музыка**: на границе фразы со сменой ведущего инструмента (`pickLayer`) или уровня энергии, не реже раза в 16 тактов.

Профили: плотность везде одна — поток ударов самой песни (у Magic Tiles нет «лёгкой версии» песни; потолок 12 нот на такт и 7 в секунду для двух больших пальцев, `DENSITY_LIMIT`). Главы отличаются механиками: EASY (глава 1) — без слайдов, дробей, аккордов и спиннеров, мало кругов, 3–4 полосы; MEDIUM (глава 2) — без дробей и аккордов; NORMAL — всё. Окна кругов короткие (2 такта, не чаще раза в 16), чтобы поток не рвался. Звёзды: около ★3 при 2 нотах/с, ★6 при 4, ★9–10 при 5,5. Ограничения играбельности (две руки, одна длинная нота, отпускание) прежние, проверяются `playability.ts`. Треки без стемов (своя музыка) читаются по ударам микса теми же правилами.

### Спиннер (v1.8)

Как в osu!. Нота `[t, 0, dur, 'spin']`: поле пустеет, в центре над линией появляется колесо (`spinGeometry`), и игрок водит пальцем (или мышью с зажатой кнопкой) по кругу — в любую сторону. Колесо стартует само, нажимать ничего не нужно; оборотов требуется `duration × SPIN_REV_PER_SEC` (1.2 об/с), дуга прогресса заполняется, лопасти крутятся вместе с пальцем. Вердикт один, в конце: все обороты — perfect, ¾ — great, половина — good, меньше — miss. Каждый полный оборот сверх нормы — `SPIN_BONUS_PER_REV` = 100 очков (без комбо, вылетает «+N» над колесом). Промах спиннера не отнимает сердце и не трогает другие механики; на клавиатуре колесо крутят частыми нажатиями любых клавиш (`SPIN_TAP_REV` = 0.15 оборота за нажатие). Куда ставит генератор: брейкдаун — тихие, но звучащие такты (intensity 0) сразу после громких, 2–4 такта, — или спокойный хвост песни; перед колесом бит тишины, после него 3,5 бита (полное падение ноты), чтобы ноты не летели, пока колесо на экране. Профили: NORMAL до 2 спиннеров, MEDIUM 1, EASY 0 — механика появляется выше лёгкого. В обучении — шаг «Крути» на шести полосах перед финалом. Чистое ядро: `SpinTracker` (углы → обороты, мёртвая зона у центра, дрожание не считается), `NoteManager.activeSpin`, тесты на всё.

### Дуэли (v2.2)

Соревнование с конкретным человеком, а не с таблицей. На экране результата кнопка «Вызвать друга» создаёт дуэль (`api/duels.ts`: трек, ник, счёт, точность, ранг за коротким id, живёт 30 дней в Upstash Redis) и отдаёт ссылку `/?duel=<id>` в системное меню «Поделиться» (или в буфер). Друг открывает ссылку и попадает на экран дуэли: обложка, «Саша · 60 775», «Побьёшь Сашу?», кнопка «Играть». Он играет тот же трек, и на результате первой строкой вердикт: «Ты побил Сашу! 61 000 против 60 775» или «Саша пока впереди». Ответ уходит в дуэль (лучший результат на ник, до 20 ответов); хозяин видит ответы в профиле, раздел «Мои дуэли» (список хранится на устройстве, `entities/duel`). Без Redis кнопка честно говорит «не получилось». Деплой теперь в один проект Vercel (`scripts/deploy.sh`), чтобы переменные окружения не терялись.

### Реклама за награду (план, v2.4)

Два места, оба — поверх уже существующего кода, не с нуля. **Магазин:** трек можно получить, посмотрев рекламу (~30 с) вместо кристаллов — в окне подтверждения покупки вторая кнопка «Смотреть рекламу — бесплатно»; если кристаллов не хватает, она становится главной. Реализация: тот же путь, что `buyTrack` в `entities/progress` (в `purchased` попадает id трека), диалог в `widgets/shop-grid`. **Игра:** когда сердца кончились, вместо мгновенного провала — предложение «Продолжить · +5 сердец за рекламу», один раз за забег, с отсчётом 5 с; отказ или истечение — обычный провал/«СТОП». Реализация: `GameSession.fail()` откладывает `finish()`, пауза музыки, после рекламы `lives.reset()` и `resumeAt()` с того же места; оверлей в `Renderer`, кнопки в `GameCanvas`. Поле, ноты и геймплей не меняются. Провайдер рекламы не выбран — интерфейс `shared/lib/ads` с заглушкой для разработки. Макеты: `.tmp/ux/screens-shop.html`, `.tmp/ux/screens-game.html`, галерея всех экранов `.tmp/ux/gallery.html`.

### Донат (план, v2.5)

Три предложения, все — поверх существующей экономики кристаллов (`recordCrystals` / `purchased[]`, как `buyTrack`), поле и геймплей не трогаются.

- **Кристаллы** (обычный попап, никогда не всплывает сам): три набора — малый 500 ◆, средний 1 500 ◆ (+10 %), большой 4 000 ◆ (+25 %). Открывается кнопкой «+» у кошелька в верхней панели и из окна «Не хватает кристаллов» в магазине (строка «Пополнить»). В попапе три монеты-варианта, цена выбранного — на кнопке «КУПИТЬ · 249 ₽».
- **«Только 48 часов»** — 3 000 ◆ по цене среднего набора, помечено «×2», с живым обратным отсчётом. Окно открывается каждые 14 дней от первого запуска и длится 48 часов (начало и конец считаются от сохранённого якоря `neon-tap:offers`); пока окно открыто, попап показывается сам один раз за сессию приложения на главном экране, а в шапке магазина рядом с «МАГАЗИН» висит золотой тег «48 ч» (остаток часов), по которому попап открывается снова.
- **«8 треков»** — восемь треков магазина открываются разом: сначала премиум (дороже — раньше), если премиумных меньше восьми — самые дорогие закрытые звёздами треки (выводится из каталога, `entities/offers/musicPack`). Попап всплывает один раз после третьего завершённого забега, затем не чаще раза в 7 дней, пока не куплен (или пока все восемь не куплены поодиночке — тогда предложение молчит). Покупка идемпотентна: уже открытые треки пропускаются.

Правила показа: на главном экране — не больше одного попапа за открытие меню, «48 часов» приоритетнее «8 треков», никогда поверх первого запуска (имя → калибровка → обучение). Одна и та же шторка (`widgets/offer-popups` на общем `shared/ui/Sheet`): герой 335 × 180 (`public/offers/<name>.webp`, а пока файла нет — процедурная SVG-заглушка: веер из восьми карт, открытый сундук с кристаллами и лучами, три горки кристаллов), золотой тег-заголовок, одна строка выгоды, монеты со стоимостью, «КУПИТЬ · цена» и «Не сейчас»; на кнопке — состояние «ОПЛАТА…», после покупки тост «Кристаллы получены» / «Треки открыты» и полёт кристаллов в фишку кошелька.

Платежи — заглушка: интерфейс `shared/lib/iap` (`Store`: `available()`, `price(sku)`, `buy(sku)` → `ok | cancel | failed`), `StubStore` «оплачивает» за 1,5 с; `?iap=off` делает магазин недоступным, и попапы просто не предлагаются. Реальный провайдер (Capacitor + Google Play / App Store) подключается заменой экземпляра в `shared/lib/iap/index.ts`; в вебе платежей нет. Цены в рублях (99 / 249 / 499 / 249 / 299 ₽) — заглушки до выбора магазина.

### Жизни, спеллы, тач-помощь

- **5 сердец**: промах −1, 25 чистых попаданий подряд +1 (до пяти показанных), спелл «сердце» +1: при полных пяти сердце золотит первое показанное — золотые сердца поверх пяти это ещё пять жизней в тех же пяти слотах (`Lives.cap` = 10, промах сначала снимает золото); сверх десяти пойманное сердце превращается в 50 кристаллов. **Бонусы без штрафа**: спеллы (сердце, часы) и ноты с кристаллом — помощь, а не задание: пропустил — ни промаха, ни разрыва комбо, ни потери сердца, нота просто исчезает и выбывает из общего счёта (`Scoring.forgive`); попал — обычный вердикт плюс бонус. Ноль сердец — провал, результат не засчитывается, RETRY.
- **Спелл «замедление»**: неоновые песочные часы в кольце; поймал — 6 секунд песни идут в 0.72× скорости *вместе с музыкой* (playbackRate + «плёночный» lowpass, вход 0.35 с, выход 0.5 с), часы и судейство идут по тому же замедленному времени, ритм не сбивается; индикатор над полем.
- **Автоподстройка задержки**: медиана последних 40 ошибок тайминга по половине вносится в оффсет (до ±80 мс); после трека с ≥ 60 попаданиями сохраняется в настройки.
- **Тач-помощь** (по умолчанию на телефоне, выключается в настройках): нажатие до 0.2 с (реальных, на быстрых уровнях окно масштабируется) *раньше* ноты «заряжает» её, и она засчитывается как Great, когда доходит до линии; повторное раннее нажатие заряд не снимает (нервный двойной тап не должен становиться промахом). На ПК тайминг строгий.

### Спецэффекты

Предрендер + пулы, без аллокаций в кадре: кольцо на Perfect, шлейф за нотой, подпрыгивание рецептора на каждом нажатии, «+очки» под судейством, искры из рецептора во время холда/дроби/слайда, счётчик «2/4» над дробью, полосатое тело дроби и наклонное тело слайда с шевронами и маркером пальца, пунктирная связка между соседними кругами, ударная волна и бегущий баннер «N COMBO» на порогах комбо, дрожь и «прыжок» цифры комбо от 20, взрыв частиц и тряска при потере сердца, «удар камеры» (зум 1.2 %) и подсветка поля на басовых ударах *самого трека* (AnalyserNode, а не сетка), смена числа полос — разделители и рецепторы физически съезжаются/разъезжаются с лёгким перелётом и световыми шлейфами, большая цифра нового числа полос, вспышка всех рецепторов в момент фиксации.

## 5. Тесты

`vitest`, окружение node, без DOM — движок спроектирован так, чтобы тестироваться без браузера:

- `Clock` — дрейф, offset, пауза/резюм
- `Scoring` / `judgeDelta` — окна, точность, ранги, «до S не хватило N»
- `NoteManager` — судейство таймингов, холды, авто-мисс, курсоры
- `OnsetDetector` — синтетический сигнал: ≥ 90 % онсетов в ±30 мс без потока ложных
- `BpmEstimator` — 128 BPM ± 2
- `ChartGenerator` — квантование, кап плотности, «≤ 2 подряд», монотонные звёзды, детерминизм
- `SaveData` — миграции, звёзды, слияние результатов
- `Calibration` — медиана против выброса
- `ParticlePool` / `ScreenShake` — ёмкость, амплитуда ≤ 4 px
- `unlocks` / `daily` / `goals` — пороги открытия, детерминированный трек дня, прогресс и награды целей, миграция сохранения v2 → v3
- `tutorial` — сценарий по долям и валидация рукописной карты (сетка 30 мс, дроби ≤ 6/с, слайды в соседнюю полосу, каждая нота внутри шага своей механики)
- `resultStats` / `JudgementTimeline` — серии, окно промахов, кривые точности и комбо, выбор окна повтора
- `PointerLanes` / `LowFpsDetector` / `layout` — мультитач, FPS-сторож, тач-зоны в портрете и ландшафте
- `themes` / `spectrum` / `cover` — цвет GOOD на любой палитре, бас из спектра, детерминизм обложек
- `History` — кап 50 попыток на трек, порядок «новые сверху», лучший результат, тренд точности
- `api/_lib/scores` — валидация тела запроса, ранжирование, «лучший на ник», rate limit; `shared/api/leaderboard` — клиент никогда не бросает (mock fetch)

## 6. Фазы

См. `docs/plans/` — по плану на фазу с чеклистом. Порядок: аудиодвижок → ядро геймплея → визуал → калибровка и мобила → автогенератор → прогрессия и меню → контент → полировка и витрина. v2 (параллельные потоки, слиты в `main`): контент и жанры, прогрессия / трек дня / цели, обучение, рекорды и онлайн-таблица, экран результата, мобильная версия, темы и ощущение.
