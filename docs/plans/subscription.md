# Подписка NEON PASS — план монетизации без рекламы

Решения владельца: рекламы нет; главная покупка — подписка; «Своя музыка» без неё — 3 песни.

## A. Что даёт подписка

**Один пакет — NEON PASS:**

| Что | Без PASS | С PASS |
|---|---|---|
| Своя музыка | 3 песни навсегда | без лимита |
| Второй шанс (сердца кончились) | 30 ◆, раз за забег | бесплатно, раз за забег |
| Новые паки треков | через 14 дней после выхода (или за ◆) | сразу |
| Кристаллы за забег | как сейчас | +50 % |
| Вид | — | золотая рамка аватара, значок PASS в рекордах и дуэлях, скин нот «Золото» |

**Цены:** 149 ₽ за 30 дней, 990 ₽ за год (год по цене 6,6 месяца, −45 %). Недельного пропуска нет: три бесплатные песни и есть пробный период, а уровни, сделанные за неделю, остаются навсегда — неделя съела бы месяц.

**Когда PASS кончился, ничего не отбирается:** сделанные уровни играются, купленное остаётся; пропадают новые загрузки, бесплатный второй шанс, +50 % и золотой вид. Очков, недоступных игрой, подписка не даёт: второй шанс есть у всех за кристаллы.

**Бесплатный игрок сохраняет всё главное:** каталог по звёздам, трек дня, цели, дуэли, бесконечный режим, онлайн-таблицу, премиум-треки за кристаллы, 3 свои песни. Наборы кристаллов и «8 треков» остаются второстепенными; у «48 часов» убрать автопоказ с таймером (срочность давит на детей).

## B. Где и как предлагать

Правила: одно окно-предложение за сессию; никогда в забеге и поверх первого запуска; без таймеров и «только сегодня»; после двух «Не сейчас» подряд автопоказ молчит 30 дней. На окне оплаты — «Покупку оформляет взрослый»; в вебе перед оплатой родительская проверка («14 + 27 = ?»), в Яндексе её роль играет окно оплаты платформы.

| Место | Триггер | Частота | Текст |
|---|---|---|---|
| Карта колоды «+ Своя музыка» | всегда в колоде | постоянно | «+ Своя музыка» · «Осталось 2 из 3»; на лимите — «Безлимит с NEON PASS» |
| 4-я загрузка | выбор 4-го нового файла | каждый раз | Окно: «Три песни уже твои!» · «С NEON PASS — сколько угодно своих песен. Уровни, которые уже есть, остаются навсегда.» · «PASS · 149 ₽ / 30 дней» · «Год · 990 ₽» · «Не сейчас» |
| Результат своей песни | 3 звезды на своей песне, использовано ≥ 2 из 3 | раз в 3 дня | Строка: «Твоя песня — на три звезды! Добавляй ещё: с PASS без лимита» |
| Результат, рекорд | новый рекорд, игрок ещё не пробовал свою музыку | раз в 7 дней | «Сыграй свою любимую песню — игра сама сделает уровень» → экран «Своя музыка» (ведём к бесплатным трём, не к оплате) |
| Корона бесконечного режима | первая корона или рекорд корон | раз в 7 дней | «Корона! С PASS второй шанс бесплатный — кругов будет больше» |
| Кадр второго шанса | сердца кончились | каждый раз, мелким текстом | под кнопкой «Продолжить · 30 ◆» — «С NEON PASS — бесплатно» |
| Магазин | всегда | первая карточка | «NEON PASS · безлимит своей музыки»; при активном — «Активен до 12.11» |
| Профиль | всегда | строка | без PASS — «NEON PASS · Узнать»; с PASS — золотой значок, дата, «Код для другого устройства» |
| Главный экран, автоокно | ≥ 5 забегов и ≥ 1 своя песня, не первая сессия | раз в 7 дней; важнее кристальных офферов | окно 4-й загрузки с заголовком «Своя музыка без лимита» |
| Новый пак | пак вышел | пока идёт ранний доступ | тег «С PASS сейчас · для всех через 9 дн.» |

## C. «Полная защита» — честно

**Граница возможного.** Уровень строится на устройстве, файл никуда не уходит. Изменённый клиент (правка JS в DevTools) всегда сгенерирует уровень без спроса; помешала бы только генерация на сервере, а она ломает обещание «файл остаётся у тебя». Защищаем **деньги и сам PASS** (подделать нельзя), а лимит делаем таким, чтобы обойти его было сложнее, чем попросить 149 ₽.

**Почему счётчик в localStorage не годится:** DevTools → Application → поменять число; очистка данных сайта; инкогнито; другой браузер; переустановка PWA. Дети узнают это за вечер на YouTube.

**Что считается:** успешно построенный уровень из нового файла. Отпечаток = SHA-256 первых 2 МБ + размер + длительность до 0,1 с. Не считаются ошибка чтения, отмена анализа, тот же файл повторно, повторная игра. Удаление песни слот не возвращает.

**Офлайн:** генерация работает. С PASS — по токену (до 7 дней с последней синхронизации, не позже даты PASS). Без PASS — по локальному счётчику, отпечатки ждут сети; сервер хранит их объединение: если их больше трёх, сделанные песни остаются, новые — через PASS.

**Яндекс Игры (запуск).** Подписок в `ysdk.payments` нет: только расходуемые и постоянные покупки. Поэтому PASS — две расходуемые покупки `pass-30` и `pass-365` (цена в янах, ставим эквивалент ~149 / ~990 ₽). Поток: `getPayments({ signed: true })` → `purchase()` → подпись уходит нашей функции → проверка HMAC-SHA256 секретным ключом из консоли → `until = max(now, until) + 30 (365) дней` по `player.getUniqueID()` → токен → `consumePurchase()`. На старте `getPurchases()` дообрабатывает незавершённые покупки (требование модерации). Без входа (`isAuthorized()`) — кнопка «Войти, чтобы PASS сохранился». Дата PASS и отпечатки дублируются в `player.setData` (облако игрока): очистка браузера лимит не сбрасывает. Домен API — в «Правила для CSP». Внешние оплаты в Яндексе запрещены: PASS из веба там не действует, и наоборот.

**Веб (второй этап).** Провайдер — **Robokassa**: принимает самозанятых, чеки в «Мой налог» уходят сами («Робочеки СМЗ»), комиссия 3,9 % карты / 3,5 % СБП до 100 тыс. ₽ в месяц, есть рекуррентные платежи. ЮKassa самозанятых принимает (3,5 %), но с 29.12.2025 не отправляет их чеки в налоговую — каждый чек пришлось бы пробивать вручную. Поток: `POST /api/pass/checkout` (счёт InvId в Redis, ссылка на оплату) → родитель платит → ResultURL → сервер сверяет подпись (Пароль №2, SHA-256), сумму и что InvId не зачтён → продлевает PASS → отвечает `OK{InvId}`; клиент берёт токен из `/api/pass/status`. На старте — пропуска без автопродления: нет забытых списаний и споров с родителями. Другое устройство — по коду PASS из профиля (до 3 устройств). Счётчик — `/api/songs/claim` (отпечатки в Upstash по анонимному id устройства); честно: инкогнито даёт новый id, так что в вебе он держит только от случайного обхода.

**Токен:** `{sub, plan, until, exp}`, подпись Ed25519; закрытый ключ только в env сервера, открытый — в клиенте. Токен не подделать; пропатченная проверка не создаст PASS в облаке и на другом устройстве.

**Хостинг.** Vercel Hobby — только некоммерческое использование, любой приём оплаты — коммерция. До веб-оплат: Vercel Pro ($20 в месяц, иностранная карта) или перенос `api/` и статики в Yandex Cloud (1 млн вызовов функций в месяц бесплатно, оплата в рублях). Рекомендую Yandex Cloud; функции Яндекс-версии — там же.

**Магазины потом.** Google Play не продаёт пользователям в РФ с 2022 года; RuStore с 01.02.2026 даёт платёжный SDK только ИП и юрлицам. Магазины — после перехода в ИП: там настоящая подписка, уведомления магазина пишут в тот же сервис прав.

**Минимум к запуску:** Яндекс — серверная проверка подписи, права на сервере, облачный счётчик; веб — вебхук Robokassa, права в Redis, токен, счётчик по id устройства. Не делаем: обфускацию, отпечатки детских устройств, генерацию на сервере.

## D. Второй шанс без рекламы

**Правило: раз за забег, 30 ◆; с NEON PASS — бесплатно.** 30 ◆ — два-три забега. Не хватает — кнопка неактивна с подписью «Нужно 30 ◆», в магазин посреди забега не зовём. Кадр, отсчёт 5 с и «3-2-1» остаются, вместо видео — мгновенное списание.

## E. План внедрения

1. **Убрать рекламу:** `shared/lib/ads`, `widgets/shop-grid/ui/AdReward.tsx`, `AdScreen.tsx`, `lib/adText.ts`, `features/buy-track/model/unlockByAd.ts`, флаг `?ads=fast`; в `features/play-chart/model/revive.ts` фаза `ad` → `pay`, в `widgets/game-canvas` — списание ◆; переписать разделы GDD «Реклама» и «Донат».
2. **Права клиента:** `entities/pass` (токен, проверка подписи, `isActive()`); SKU `pass-30`, `pass-365` в `shared/lib/iap/types.ts`; `YandexStore` и `WebStore` рядом с `StubStore`.
3. **Свои песни:** `entities/custom-song` (IndexedDB: файл, карта, отпечаток — на устройстве), `features/song-quota` (счётчик, claim, синхронизация); проверка в `widgets/song-drop-zone` до генерации; карта «+ Своя музыка» в `widgets/track-list`.
4. **Окно PASS:** `widgets/pass-paywall` на `shared/ui/Sheet`; точки раздела B в `result-breakdown`, `shop-grid`, профиле, `offer-popups/model/autoOffer.ts`.
5. **Сервер:** `api/pass/verify-yandex.ts`, `checkout.ts`, `robokassa-result.ts`, `status.ts`, `restore.ts`, `api/songs/claim.ts`, `api/_lib/pass.ts` с тестами подписей на фикстурах; ключи `neon-tap:pass:<sub>`, `:inv:<id>`, `:songs:<sub>`, `:code:<hash>`.
6. **Выгоды:** бесплатный второй шанс, +50 % в `recordCrystals`, рамка, значок, скин нот, `earlyUntil` у пака в `tracks.json`.
7. **Сборка для Яндекса:** SDK, `getPurchases` на старте, облачные данные игрока.
8. **Веб-оплата и переезд хостинга.**

**Владелец делает сам (агент секретов не видит):** оформить самозанятость в «Мой налог»; в консоли Яндекс Игр — единая лицензионная схема, подтверждение самозанятости, покупки, товары `pass-30` / `pass-365` (RU/EN), секретный ключ подписи, правило CSP; в Robokassa — магазин, Пароли №1/№2, SHA-256, ResultURL, «Робочеки СМЗ»; положить в env `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`, `YANDEX_PURCHASE_SECRET`, `ROBOKASSA_LOGIN`, `ROBOKASSA_PASS1`, `ROBOKASSA_PASS2`, `PASS_SIGNING_KEY`; выбрать хостинг; опубликовать оферту, политику конфиденциальности и правила возврата; сделать тестовые покупки.
